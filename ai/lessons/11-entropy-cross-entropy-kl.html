Part 3 · Probability & statistics

Entropy, cross-entropy & KL

Every language model you will train in this course minimizes one number: the cross-entropy between the text and the model's predictions. This lesson builds that number from one idea, "how surprised am I?". From it come entropy, cross-entropy, KL divergence and perplexity. Along the way you'll see why the KL penalty in RLHF behaves the way it does.

By the end you can

  • Define surprise $-\log p$ and explain why the logarithm is the only sensible choice.
  • Compute entropy, and read it as the shortest possible average code length.
  • Compute cross-entropy and KL divergence, prove $\mathrm{KL}\ge 0$, and explain why cross-entropy is the language-model loss.
  • Predict what forward and reverse KL do when the model is too simple (mode-covering vs mode-seeking).
  • Convert a loss into perplexity, and compute log-softmax without overflow.

    1. Surprise: −log p

    Start with a single event of probability $p$. We want a number $s(p)$ that measures how surprised we should be when it happens. Three requirements pin it down:

    • A certain event is no surprise: $s(1) = 0$.
    • Rarer means more surprising: $s$ decreases as $p$ grows.
    • Surprises of independent events add. Seeing two independent events (probability $p\,q$, lesson 08) should be exactly as surprising as seeing one and then the other: $s(pq) = s(p) + s(q)$.

    The third rule turns products into sums, and that is precisely what logarithms do. Up to the choice of base, the only continuous solution is

    $$s(p) = -\log p = \log\frac{1}{p}.$$

    The base only sets the unit. With $\log_2$ the unit is the bit: an event with $p = 1/2$ (a fair coin landing heads) carries exactly 1 bit of surprise, and $p = 1/8$ carries 3 bits, as much as three heads in a row. With the natural log the unit is the nat. ML code uses nats because log is ln. Converting is a constant factor: $1\text{ nat} = 1/\ln 2 \approx 1.443$ bits.

    Try it: slide $p$. Every time you halve $p$, the surprise grows by exactly one bit: the curve is linear in "number of halvings". Push $p$ toward 0 and the surprise heads to infinity. A model that gives the true answer probability 0 is infinitely wrong. Remember that when we reach the loss function.

    2. Entropy: average surprise

    A random variable $X$ with distribution $p$ (lesson 08) produces outcomes with different surprises. Its entropy is the expected surprise (expectation from lesson 09):

    $$H(p) = \mathbb{E}_{x\sim p}\big[-\log p(x)\big] = -\sum_x p(x)\log p(x).$$

    We use the convention $0\log 0 = 0$: outcomes that never happen contribute nothing. (This is the limit $\lim_{p\to0} p\log p = 0$: the surprise grows, but its weight shrinks faster.)

    Entropy measures how unpredictable a distribution is. Two extremes make this concrete:

    • A certain outcome ($p = (1, 0, \dots, 0)$) has $H = 0$. Nothing to learn.
    • The uniform distribution over $K$ outcomes has $H = \sum_x \frac1K \log K = \log K$. That's the maximum possible (problem 6 proves it).

    The simplest case is a coin with $P(\text{heads}) = p$:

    $$H(p) = -p\log_2 p - (1-p)\log_2(1-p) \quad\text{bits}.$$
    Try it: slide the coin's bias $p$. The thick curve is the entropy; the dashed curves are its two terms, heads' share $p\cdot(-\log_2 p)$ and tails' share. The peak is the fair coin at exactly 1 bit. At $p = 0.9$ a flip carries only about 0.47 bits: heads is so expected that it tells you little.
    Worked example

    A fair six-sided die: $H = -6\cdot\frac16\log_2\frac16 = \log_2 6 \approx 2.585$ bits.

    A loaded die with $p = (\frac12, \frac1{10}, \frac1{10}, \frac1{10}, \frac1{10}, \frac1{10})$: $H = \frac12\log_2 2 + 5\cdot\frac1{10}\log_2 10 = 0.5 + 0.5\times3.322 \approx 2.161$ bits. Loading the die made it more predictable, so the entropy dropped.

    3. Entropy is the best possible average code length

    Entropy isn't just a definition. Shannon proved it has an operational meaning. Suppose you must send a long stream of symbols drawn from $p$ over a wire as bits, using a prefix code (no codeword is the start of another, so the stream decodes without separators). Then:

    Source coding theorem. No prefix code can use fewer than $H(p)$ bits per symbol on average. And there is always a code using fewer than $H(p) + 1$. The ideal length for symbol $x$ is its surprise, $-\log_2 p(x)$ bits: common symbols get short codewords, rare ones long codewords.

    Huffman's algorithm builds an optimal code greedily. Put every symbol in a pile. Repeatedly take the two least likely items, join them under a new node whose probability is their sum, and label the two branches 0 and 1. When one tree remains, each symbol's codeword is the path from the root.

    Worked example

    Symbols A, B, C, D with $p = (\frac12, \frac14, \frac18, \frac18)$.

    Merge the two smallest, C and D, into a node of weight $\frac14$. Now the smallest are B ($\frac14$) and CD ($\frac14$): merge into BCD ($\frac12$). Finally merge A with BCD. Reading paths: A = 0, B = 10, C = 110, D = 111.

    Average length: $\frac12\cdot1 + \frac14\cdot2 + \frac18\cdot3 + \frac18\cdot3 = 1.75$ bits. Entropy: $\frac12\cdot1 + \frac14\cdot2 + \frac18\cdot3 + \frac18\cdot3 = 1.75$ bits. They're equal because every probability is a power of $\frac12$, so every ideal length $-\log_2 p$ is a whole number. A naive 2-bits-per-symbol code wastes 0.25 bits per symbol.

    Try it: pick a distribution. For each symbol, the blue bar is its ideal length $-\log_2 p$ (its surprise) and the orange bar is the length of its Huffman codeword (printed underneath). Huffman lengths are whole bits, so they can only approximate the ideal. Check the readout: the average code length always lands in $[H, H+1)$.

    This gives entropy a tangible meaning: the number of yes/no questions you need, on average, to pin down the outcome if you ask cleverly. It's also why a good predictor is a good compressor. A model that predicts the next token well can encode text in few bits. Language modeling and compression are the same problem.

    4. Cross-entropy: paying for the wrong model

    Now suppose the data comes from $p$, but you believe it comes from $q$. You build your code (or your predictions) from $q$, so symbol $x$ costs you $-\log q(x)$. Your average cost is the cross-entropy:

    $$H(p, q) = \mathbb{E}_{x\sim p}\big[-\log q(x)\big] = -\sum_x p(x)\log q(x).$$

    Read it as: outcomes arrive at the rate $p$, and each is scored by the surprise $q$ assigns to it. If $q = p$ you pay exactly $H(p)$. Section 5 shows you can never do better than that.

    Why this is the language-model loss

    A language model reads a context and outputs a distribution $q_\theta(\cdot\mid\text{context})$ over the vocabulary. Training text gives, for each context, the token that actually came next. Think of that token as a sample from the true distribution $p$ of next tokens. The loss on one position is the surprise of the true token:

    $$\ell = -\log q_\theta(x_{\text{true}} \mid \text{context}).$$

    That's the cross-entropy between a one-hot target ($p$ puts all its mass on $x_{\text{true}}$) and the model's prediction. Averaged over millions of positions, it's a Monte Carlo estimate (lesson 08) of $H(p_{\text{data}}, q_\theta)$. It's also the negative log-likelihood of the data, so minimizing it is maximum-likelihood estimation (lesson 10). Three names, one number.

    Worked example

    Context: "the cat sat on the". Over a 5-word vocabulary, the model predicts $q = (\text{mat } 0.6,\ \text{rug } 0.2,\ \text{floor } 0.1,\ \text{cat } 0.05,\ \text{moon } 0.05)$.

    If the true next word is "mat": loss $= -\ln 0.6 \approx 0.511$ nats. If it's "moon": loss $= -\ln 0.05 = \ln 20 \approx 2.996$ nats. Only the probability on the correct token enters the loss. But the probabilities must sum to 1, so pushing up "mat" pulls everything else down. That's why the gradient touches every logit (problem 9).

    A model that hasn't learned anything predicts uniformly over GPT-2's 50,257 tokens and pays $\ln 50257 \approx 10.82$ nats on every token. When you train your tiny GPT in lesson 24, the loss starts near $\ln(\text{vocab size})$. Now you know why.

    5. KL divergence: the extra cost of being wrong

    How much does believing $q$ cost you beyond the unavoidable $H(p)$? That excess is the Kullback–Leibler divergence:

    $$\mathrm{KL}(p\,\|\,q) = H(p, q) - H(p) = \sum_x p(x)\log\frac{p(x)}{q(x)}.$$

    Equivalently, $\mathrm{KL}(p\|q) = \mathbb{E}_{x\sim p}\!\big[\log p(x) - \log q(x)\big]$: the average gap in log-probability, measured where $p$ puts its mass.

    KL is never negative (Gibbs' inequality)

    The proof uses one fact: $\ln t \le t - 1$ for all $t > 0$, with equality only at $t = 1$. (The line $t-1$ is the tangent to $\ln t$ at $t=1$, and $\ln$ is concave, so it lies below every tangent.) Sum over the $x$ with $p(x) > 0$:

    $$-\mathrm{KL}(p\|q) = \sum_x p(x)\ln\frac{q(x)}{p(x)} \;\le\; \sum_x p(x)\Big(\frac{q(x)}{p(x)} - 1\Big) = \sum_{x:\,p(x)>0} q(x) \;-\; 1 \;\le\; 0.$$

    So $\mathrm{KL}(p\|q) \ge 0$. Equality requires $q(x)/p(x) = 1$ everywhere, so it holds only when $q = p$. $\blacksquare$

    Since $H(p,q) = H(p) + \mathrm{KL}(p\|q)$ and $H(p)$ doesn't depend on the model, minimizing cross-entropy over $q$ is the same as minimizing $\mathrm{KL}(p\|q)$. The best achievable loss is the entropy of the data itself. A language model's loss can never reach 0 on real text, because real text is genuinely unpredictable.

    KL is not a distance

    KL is zero only when $p = q$, but it is asymmetric: in general $\mathrm{KL}(p\|q) \ne \mathrm{KL}(q\|p)$. Take $p = (0.5, 0.5)$ and $q = (0.9, 0.1)$:

    $$\begin{aligned}\mathrm{KL}(p\|q) &= 0.5\ln\tfrac{0.5}{0.9} + 0.5\ln\tfrac{0.5}{0.1} \approx 0.511 \text{ nats},\\ \mathrm{KL}(q\|p) &= 0.9\ln\tfrac{0.9}{0.5} + 0.1\ln\tfrac{0.1}{0.5} \approx 0.368 \text{ nats}.\end{aligned}$$

    The asymmetry comes from whose probabilities do the averaging. $\mathrm{KL}(p\|q)$ blows up when $q(x) \approx 0$ where $p(x) > 0$: the model calls something impossible that actually happens. $\mathrm{KL}(q\|p)$ blows up in the opposite case.

    Try it: drag the bar tops. Blue is the true distribution $p$ and orange is the model $q$; the other bars rescale so each still sums to 1. The right panel shows the split $H(p,q) = H(p) + \mathrm{KL}(p\|q)$. Press "q = p" and watch both KLs hit 0. Now drag one orange bar down to almost nothing where blue is large: $\mathrm{KL}(p\|q)$ explodes while $\mathrm{KL}(q\|p)$ barely moves.

    6. Forward vs reverse KL: covering vs seeking

    The asymmetry matters most when the model family is too simple to match the target exactly. Then you have to choose which mistakes to accept, and the KL direction decides it. Classic setup: the target $p$ is bimodal (two bumps), and $q$ must be a single Gaussian $\mathcal{N}(\mu, \sigma^2)$ (lesson 09).

    • Forward KL, $\mathrm{KL}(p\|q) = \mathbb{E}_{p}[\log p - \log q]$, is averaged where the data lives. Wherever $p$ has mass, $q$ must not be tiny, or $-\log q$ explodes. So $q$ stretches to cover both modes, putting a lot of mass in the empty gap between them. This is mode-covering (or "mean-seeking"). For a Gaussian $q$, the optimum exactly matches $p$'s mean and variance (problem 10).
    • Reverse KL, $\mathrm{KL}(q\|p) = \mathbb{E}_{q}[\log q - \log p]$, is averaged where the model lives. $q$ is punished for putting mass where $p$ is tiny, like the gap, and not punished at all for ignoring regions it doesn't visit. So $q$ picks one mode and fits it tightly. This is mode-seeking.
    Try it: top, the bimodal target $p$ (green) and a Gaussian $q$ (purple). Bottom, the loss landscape over $(\mu,\sigma)$ for the chosen direction (darker = lower KL); drag the dot to move $q$. Press "descend forward KL": $q$ settles at $\mu = 0$ with a wide $\sigma \approx 2.09$, straddling the gap. Reset, then press "descend reverse KL": $q$ snaps onto one bump with $\sigma \approx 0.6$, and $\mathrm{KL}(q\|p) \approx \ln 2$ (it misses half the mass). Switch the landscape to reverse. It has two deep valleys (one per mode) and a shallow trap near $\mu=0$: start from $\mu = 0, \sigma = 2$ and descent gets stuck there.

    Pretraining minimizes cross-entropy on data, which is forward KL from the data to the model. That makes base models mode-covering: they hedge, spread probability over every plausible continuation, and stay diverse. RLHF (lesson 28) fine-tunes a policy $\pi$ to maximize reward minus a penalty $\beta\,\mathrm{KL}(\pi\|\pi_{\text{ref}})$. That's a reverse KL, estimated from the policy's own samples. It strongly punishes $\pi$ for producing text the reference model finds implausible, which keeps outputs fluent and on-distribution. But it barely punishes dropping modes the reference had. The result is mode-seeking behavior: RLHF-tuned models are more confident, less diverse, and tend to converge on a few favored answers. DPO (lesson 29) inherits the same KL-regularized objective.

    7. Perplexity and the numerically stable loss

    Cross-entropy in nats is hard to feel. Perplexity undoes the log:

    $$\mathrm{PPL} = \exp\!\Big(\frac1T\sum_{t=1}^T -\ln q(x_t\mid x_{\lt t})\Big) = e^{\text{CE}} \quad(\text{or } 2^{\text{CE in bits}}).$$

    It's the effective branching factor. A model that spreads probability uniformly over $k$ tokens has CE $= \ln k$ and perplexity exactly $k$. So "perplexity 20" means the model is, on average, as unsure as if it were choosing uniformly among 20 tokens. Lower is better. 1 is perfect, and the vocabulary size is the score of a model that learned nothing.

    Worked example

    A model assigns probabilities $0.5, 0.25, 0.125, 0.5$ to the four actual tokens of a text. In bits the surprises are $1, 2, 3, 1$, with mean $1.75$ bits. Perplexity $= 2^{1.75} \approx 3.364$. The same answer in nats: mean surprise $1.75\ln2 \approx 1.213$, and $e^{1.213} \approx 3.364$.

    Computing log-softmax without overflow

    Models output logits $z$, and probabilities come from softmax: $q_i = e^{z_i}/\sum_j e^{z_j}$. The loss needs $\log q_y = z_y - \log\sum_j e^{z_j}$. Computing this naively breaks easily. $e^{1000}$ overflows to inf, and for very negative logits $e^{z}$ underflows to 0, so $\log 0 = -\infty$. The fix is one line of algebra. For any constant $m$,

    $$\log\sum_j e^{z_j} = \log\Big(e^{m}\sum_j e^{z_j - m}\Big) = m + \log\sum_j e^{z_j - m}.$$

    Choose $m = \max_j z_j$. Now the largest exponent is $e^0 = 1$, nothing overflows, and the sum is at least 1, so its log is finite. This is the log-sum-exp trick, and $\text{log\_softmax}(z) = z - \text{logsumexp}(z)$ is how every framework computes the cross-entropy loss. For example, with $z = (1000, 1001, 1002)$: $m = 1002$, and $\log q_3 = -\ln(e^{-2} + e^{-1} + 1) \approx -0.408$, with no overflow anywhere.

    Never compute log(softmax(z)) in two steps. When a probability underflows to 0 you get $-\infty$, and its gradient becomes NaN, which silently poisons training. Use a fused log_softmax or cross_entropy(logits, target). In PyTorch (lesson 19), F.cross_entropy takes logits, not probabilities, for exactly this reason.

    8. Problems

    Do these with pencil and paper before opening the solutions.

    Problem 1
    warm-up

    An event has probability $1/8$. What is its surprise in bits? In nats?

    Enter the surprise in bits:

    Solution

    $-\log_2(1/8) = 3$ bits. In nats, $\ln 8 \approx 2.079$, which is $3 \times \ln 2$.

    Problem 2
    warm-up

    What is the entropy, in bits, of a coin with $P(\text{heads}) = 0.9$?

    Solution

    $H = -0.9\log_2 0.9 - 0.1\log_2 0.1 = 0.9(0.152) + 0.1(3.322) \approx 0.137 + 0.332 = 0.469$ bits. Compare with 1 bit for a fair coin.

    Problem 3
    core

    Five symbols have probabilities $(0.4, 0.2, 0.2, 0.1, 0.1)$. Build a Huffman code by hand and compute its average length in bits. Compare with the entropy.

    Average length:

    Hint

    Merge 0.1 + 0.1 first, then the two smallest of {0.4, 0.2, 0.2, 0.2}. When there are ties, any choice gives the same average length (but possibly different individual lengths).

    Solution

    One valid tree: merge 0.1+0.1 → 0.2, merge 0.2+0.2 → 0.4, merge 0.2+0.4 → 0.6, merge 0.4+0.6 → 1. Lengths: $(1, 2, 3, 4, 4)$, average $0.4 + 0.4 + 0.6 + 0.4 + 0.4 = 2.2$ bits. (Another tie-breaking gives lengths $(2,2,2,3,3)$, also average $2.2$.) Entropy: $H \approx 2.122$ bits. So $H \le 2.2 \lt H + 1$, as the theorem promises. The gap exists because these probabilities aren't powers of $\frac12$.

    Problem 4
    core

    For $p = (0.5, 0.5)$ and $q = (0.9, 0.1)$, compute $\mathrm{KL}(p\|q)$ and $\mathrm{KL}(q\|p)$ in nats. Which one is bigger, and why does that make sense?

    Solution

    $\mathrm{KL}(p\|q) = 0.5\ln(0.5/0.9) + 0.5\ln(0.5/0.1) = 0.5(-0.588) + 0.5(1.609) \approx 0.511$. $\mathrm{KL}(q\|p) = 0.9\ln1.8 + 0.1\ln0.2 = 0.529 - 0.161 \approx 0.368$. The first is larger because $p$ sends half its samples to the second outcome, where $q$ gives only 0.1 (surprise $\ln 10$). In the reverse direction, $q$ rarely visits that outcome, so the mismatch there carries little weight.

    Problem 5
    core

    A freshly initialized language model with a 50,257-token vocabulary outputs almost exactly uniform predictions. What cross-entropy loss (nats per token) do you expect at step 0? What perplexity?

    Loss in nats:

    Solution

    Every token gets $q = 1/50257$, so the loss is $-\ln(1/50257) = \ln 50257 \approx 10.825$ nats, and perplexity is $e^{10.825} = 50257$. If your loss at initialization is far above $\ln V$, the initial logits are too large and the model is confidently wrong. That's a standard sanity check (lesson 18).

    Problem 6
    core · proof

    Let $u$ be the uniform distribution over $K$ outcomes. Show that $\mathrm{KL}(p\|u) = \log K - H(p)$. Conclude that the uniform distribution has the maximum entropy among all distributions on $K$ outcomes.

    Solution

    $\mathrm{KL}(p\|u) = \sum_x p(x)\log\frac{p(x)}{1/K} = \sum_x p(x)\log p(x) + \log K\sum_x p(x) = -H(p) + \log K$. By Gibbs, $\mathrm{KL}\ge 0$, so $H(p) \le \log K$, with equality exactly when $p = u$. Entropy measures how far $p$ is from "knowing nothing".

    Problem 7
    core

    A model assigns probabilities $0.5, 0.25, 0.125, 0.5$ to the four true tokens of a text. What is its perplexity?

    Solution

    Mean surprise in bits is $(1 + 2 + 3 + 1)/4 = 1.75$, so $\mathrm{PPL} = 2^{1.75} \approx 3.364$. Note that perplexity is the geometric mean of $1/q$: $(2\cdot4\cdot8\cdot2)^{1/4} = 128^{1/4} \approx 3.364$.

    Problem 8
    core

    Compute $\text{log\_softmax}(z)_3$ for logits $z = (1000, 1001, 1002)$. What does the naive formula $\ln\big(e^{z_3} / \sum_j e^{z_j}\big)$ give in float64?

    Solution

    Subtract the max: $z - 1002 = (-2, -1, 0)$, so $\log q_3 = 0 - \ln(e^{-2} + e^{-1} + 1) = -\ln 1.5032 \approx -0.4076$. Naively, $e^{1000}$ overflows to inf (float64 tops out near $e^{709}$), so you get $\inf/\inf = $ NaN. Softmax only depends on differences of logits, and the trick exploits exactly that.

    Problem 9
    core · derivation

    Let $\ell(z) = -\log \text{softmax}(z)_y$ for logits $z\in\mathbb{R}^K$ and true class $y$. Show that $\dfrac{\partial \ell}{\partial z_k} = q_k - [k = y]$, where $q = \text{softmax}(z)$. Interpret the result.

    Hint

    Write $\ell = -z_y + \log\sum_j e^{z_j}$ first. The derivative of logsumexp is softmax.

    Solution

    $\ell = -z_y + \log\sum_j e^{z_j}$. The first term has derivative $-[k=y]$. The second: $\frac{\partial}{\partial z_k}\log\sum_j e^{z_j} = \frac{e^{z_k}}{\sum_j e^{z_j}} = q_k$. So $\nabla_z \ell = q - \text{onehot}(y)$. Interpretation: the gradient is "prediction minus truth". It pushes the true logit up by $1 - q_y$ and every other logit down by its probability. It's zero only when the model puts probability 1 on the right answer. This clean form is why softmax and cross-entropy are always paired. You'll implement it in lesson 14 and see it fall out of backprop in lesson 17.

    Problem 10
    stretch

    (a) Show that minimizing forward KL $\mathrm{KL}(p\|q)$ over Gaussians $q = \mathcal{N}(\mu,\sigma^2)$ gives $\mu = \mathbb{E}_p[x]$ and $\sigma^2 = \mathrm{Var}_p[x]$ (moment matching). (b) For $p = \frac12\mathcal{N}(-2, 0.5^2) + \frac12\mathcal{N}(2, 0.5^2)$, what $\sigma$ does forward KL choose?

    Hint

    Only the cross-entropy term depends on $q$: minimize $\mathbb{E}_p[-\log q(x)] = \mathbb{E}_p\big[\frac{(x-\mu)^2}{2\sigma^2}\big] + \log\sigma + \text{const}$. Set the derivatives in $\mu$ and $\sigma$ to zero. For (b), the variance of a mixture is the average within-component variance plus the variance of the component means.

    Solution

    (a) $\partial/\partial\mu$: $-\mathbb{E}_p[x-\mu]/\sigma^2 = 0 \Rightarrow \mu = \mathbb{E}_p[x]$. $\partial/\partial\sigma$: $-\mathbb{E}_p[(x-\mu)^2]/\sigma^3 + 1/\sigma = 0 \Rightarrow \sigma^2 = \mathbb{E}_p[(x-\mu)^2]$. This is the same calculation as the Gaussian MLE in lesson 10, with the data average replaced by $\mathbb{E}_p$.

    (b) Mean $0$. Variance $= 0.25 + \frac12(4) + \frac12(4) = 4.25$, so $\sigma = \sqrt{4.25} \approx 2.062$. That's far wider than either bump, and most of $q$'s mass sits in the gap where $p$ is nearly zero. That's mode-covering.

    9. Quick check

    A language model's validation loss is 2.0 nats per token. What is its perplexity?
    Perplexity is $e^{\text{CE}}$ when CE is in nats: $e^{2} \approx 7.39$. $2^2$ would be right only if the loss were measured in bits.
    During training, your model assigns probability exactly 0 to a token that appears in a training example. What happens to the cross-entropy loss?
    The $0\log0=0$ convention applies to outcomes the data never produces. Here the data produced it and the model called it impossible: $-\log q = \infty$. Softmax outputs are never exactly 0 in exact arithmetic, which is one reason we compute in log space.
    Why is minimizing cross-entropy $H(p_{\text{data}}, q_\theta)$ equivalent to minimizing $\mathrm{KL}(p_{\text{data}}\|q_\theta)$?
    $H(p,q) = H(p) + \mathrm{KL}(p\|q)$. A constant offset doesn't change where the minimum is. It does mean the CE loss bottoms out at $H(p_{\text{data}}) \gt 0$, not at zero.
    You fit a single Gaussian $q$ to a two-peaked target $p$. Which objective yields a $q$ that sits tightly on one peak and ignores the other?
    Reverse KL averages over $q$'s own samples, so it only cares that wherever $q$ goes, $p$ is high. Covering a single peak satisfies that. Forward KL (and therefore cross-entropy) averages over $p$'s samples, so it forces $q$ to cover both peaks.
