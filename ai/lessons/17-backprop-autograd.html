Backprop & building micro-autograd

In lesson 16 you derived a backward pass by hand for one specific network. Do that for a transformer and you'll be at it for weeks, and you'll get it wrong. Backpropagation is the observation that you never have to. Break any computation into tiny pieces whose derivatives you know, then let the chain rule run backwards through the pieces automatically. In this lesson you build the engine that does it: about 100 lines of Python, and the same idea that powers PyTorch.

By the end you can

  • Draw the computation graph of an expression and run its forward and backward passes by hand.
  • Explain why every node only needs its local derivative, and why the order of the backward pass must be reverse topological.
  • Explain why gradients accumulate (+=) when a value is used more than once.
  • Implement a scalar autograd engine (Value) and train a small neural net with it.
  • Generalize from scalars to tensors using vector–Jacobian products, the way real frameworks do.

    1. Why automate the chain rule?

    Training needs $\nabla_\theta L$, the derivative of one scalar loss with respect to every parameter. There are three ways to get it:

    MethodHowCost for $P$ parametersVerdict
    By handDerive formulas like lesson 16 §7your time, for every new architectureerror-prone, doesn't scale
    Numerical$\frac{L(\theta + h e_i) - L(\theta - he_i)}{2h}$ for each $i$ (lesson 06)$2P$ forward passesGPT-2 small: 248 million forward passes per step. Only good for testing.
    Reverse-mode autodiff (backprop)Chain rule over the computation graph, output to inputsabout 2–3 forward passes, whatever $P$ iswhat everyone uses

    The last row looks too good to be true. By the end of §4 you'll see exactly why it works. Every intermediate result's gradient is computed once and reused by everything upstream of it.

    2. Computation graphs

    Any program that computes a number from inputs using arithmetic and elementary functions can be drawn as a directed acyclic graph (DAG). Leaves are inputs and parameters. Every other node is one primitive operation applied to the nodes that point into it. Take

    $$L = (a\cdot b + c)\cdot f, \qquad a = 2,\; b = -3,\; c = 10,\; f = -2.$$

    Name the intermediates: $e = a\cdot b$, $d = e + c$, $L = d\cdot f$. The forward pass evaluates nodes in an order where every node comes after its inputs: $e = -6$, $d = 4$, $L = -8$.

    The backward pass asks, for every node $v$: if I nudged $v$, how much would $L$ move? That's $\partial L/\partial v$, which we'll call $v$'s gradient (written v.grad). Start at the output with $\partial L/\partial L = 1$ and walk backwards:

    Try it: press step repeatedly. First the forward pass fills in each node's data in topological order. Then the backward pass fills in each grad, from the output back to the leaves. At every backward step the readout shows the one rule being applied: input.grad += local derivative × output.grad. Switch to the "neuron" graph: that's $\tanh(x_1w_1 + x_2w_2 + b)$, one unit of lesson 16. Then try the "reuse" graph (§5).
    Worked example: backprop by hand

    Forward: $e = ab = -6$, $d = e + c = 4$, $L = df = -8$.

    Backward, one node at a time, always "local derivative × gradient arriving from above":

    • $\partial L/\partial L = 1$.
    • $L = d\cdot f$: $\;\partial L/\partial d = f\cdot 1 = -2$, $\;\partial L/\partial f = d \cdot 1 = 4$.
    • $d = e + c$: local derivatives are both 1, so $\partial L/\partial e = 1\cdot(-2) = -2$ and $\partial L/\partial c = -2$.
    • $e = a\cdot b$: $\;\partial L/\partial a = b\cdot(-2) = 6$, $\;\partial L/\partial b = a\cdot(-2) = -4$.

    Sanity check: $L = (ab+c)f$, so $\partial L/\partial a = bf = (-3)(-2) = 6$. ✓ Nudge $a$ up by $0.01$ and $L$ goes from $-8$ to about $-7.94$.

    3. Local gradients: each node knows only itself

    Notice what each backward step needed: the node's own inputs, and the gradient of $L$ with respect to the node's output. It didn't need to know anything about the rest of the graph. This is just the chain rule (lesson 05): if $L$ depends on $x$ only through $z = g(x, y)$, then

    $$\frac{\partial L}{\partial x} = \underbrace{\frac{\partial L}{\partial z}}_{\text{upstream (from above)}}\cdot\underbrace{\frac{\partial z}{\partial x}}_{\text{local}}.$$

    So an autograd engine only needs a short table of primitive operations, each with its local derivative:

    Op $z =$Local derivativesBackward rule ("gate" behavior)
    $x + y$$1,\;1$distributes: both inputs get $\bar z$ unchanged
    $x\cdot y$$y,\;x$swaps: $\bar x \mathrel{+}= y\,\bar z$, $\bar y \mathrel{+}= x\,\bar z$
    $x^k$ ($k$ constant)$kx^{k-1}$$\bar x \mathrel{+}= kx^{k-1}\bar z$
    $e^x$$e^x = z$reuses the output: $\bar x \mathrel{+}= z\,\bar z$
    $\log x$$1/x$$\bar x \mathrel{+}= \bar z / x$
    $\tanh x$$1 - z^2$$\bar x \mathrel{+}= (1-z^2)\bar z$
    $\mathrm{relu}(x)$$\mathbb{1}[x>0]$routes: passes $\bar z$ if the unit was on, else blocks
    $\max(x, y)$$\mathbb{1}[x>y],\;\mathbb{1}[y\ge x]$routes the whole gradient to the winner

    Here $\bar v$ is shorthand for $\partial L/\partial v$. Subtraction, division and so on don't need entries. $x - y = x + (-1)\cdot y$ and $x / y = x\cdot y^{-1}$ are built from the table, and their gradients come out right automatically. You'll do exactly this in the workbook.

    Think of the gradient as "blame" flowing backwards. A + node passes the full blame to both inputs. A × node gives each input blame in proportion to the other input: if $a$ was multiplied by a big $b$, then $a$ had a big effect. A ReLU node that was off blocks blame completely. That is how dead units stop learning.

    4. Order matters: reverse topological order

    A node may only push its gradient down to its inputs once its own gradient is complete. That means once every node that uses it has already been processed. An ordering where each node comes after all of its inputs is a topological order. Run the backward pass in reverse topological order and every node is finished before it's needed.

    Finding one is a depth-first search. Visit a node's inputs first, then append the node (a "post-order" traversal):

    def topo_order(root):
    order, visited = [], set()
    def visit(v):
        if v not in visited:
            visited.add(v)
            for child in v._prev:     # the inputs v was computed from
                visit(child)
            order.append(v)           # after all of its inputs
    visit(root)
    return order                       # backward: for v in reversed(order): v._backward()
    Try it: you are the autograd engine. Click the operation nodes in the order you'd run their _backward(). The graph is $L = m\cdot\tanh(m + c)$ with $m = a\cdot b$. The value $m$ is used twice, by the + node and by the final ×. A breadth-first walk from $L$ would reach $m$ too early, before its gradient has arrived from both consumers. Try clicking $m$ second and see why that's rejected.

    Why reverse mode is so cheap

    In Jacobian language (lesson 07), a chain of layers $\mathbf{x}\to\mathbf{h}_1\to\mathbf{h}_2\to L$ has gradient

    $$\underbrace{\nabla_\mathbf{x}L^\top}_{1\times n} = \underbrace{\frac{\partial L}{\partial\mathbf{h}_2}}_{1\times n}\;\underbrace{\frac{\partial\mathbf{h}_2}{\partial\mathbf{h}_1}}_{n\times n}\;\underbrace{\frac{\partial\mathbf{h}_1}{\partial\mathbf{x}}}_{n\times n}.$$

    Matrix multiplication is associative, so you can evaluate this product in either order. Forward mode goes right to left: matrix × matrix products of cost $n^3$, or $n$ passes, one per input direction. Reverse mode goes left to right, and the running product is always a single row vector. Each step is a vector–Jacobian product of cost $n^2$, often much less. Because the loss is a scalar, one backward sweep gives the gradient for all inputs at once. That's the whole trick, and it's why backprop costs about the same as a couple of forward passes.

    5. A node used twice: gradients add up

    When a value feeds into several places, nudging it changes $L$ along every path. The multivariable chain rule (lesson 06) says the effects add. If $L$ depends on $x$ through $u_1(x), \dots, u_k(x)$, then

    $$\frac{\partial L}{\partial x} = \sum_{j=1}^{k}\frac{\partial L}{\partial u_j}\,\frac{\partial u_j}{\partial x}.$$

    In code, each consumer's _backward adds its contribution: x.grad += .... Use = instead and the last consumer silently overwrites the others. This is the most common bug in hand-written autograd.

    Worked example: a value used four times

    Graph: $s = x\cdot x$, $y = s + x$, $L = y\cdot x$. So $x$ feeds the graph through four edges. Forward: $s = 9$, $y = 12$, $L = 36$.

    Backward: $\bar L = 1$. Through $L = y\cdot x$: $\bar y = x\cdot1 = 3$, and $\bar x \mathrel{+}= y\cdot 1 = 12$. Through $y = s + x$: $\bar s = 3$ and $\bar x \mathrel{+}= 3$, so now $\bar x = 15$. Through $s = x\cdot x$: both inputs are $x$, so $\bar x \mathrel{+}= x\cdot\bar s = 9$ twice, giving $\bar x = 33$.

    Check: $L = x^3 + x^2$, so $L' = 3x^2 + 2x = 27 + 6 = 33$. ✓ With = instead of +=, you'd get 9.

    Pick "reuse" in the step-through figure above and tick "buggy" to watch the wrong answer appear. The same rule explains lesson 16 problem 6. A broadcast bias is one value used by every row of the batch, so its gradient is a sum over the batch.

    Accumulation is also why PyTorch makes you call optimizer.zero_grad() every step. .grad keeps adding across backward() calls, so if you forget to zero it you train on the sum of all past gradients. (Sometimes that's deliberate: "gradient accumulation" sums over several small batches to simulate one big one.)

    6. The Value class

    Here's the whole design. Each Value stores a number, its gradient, the Values it was made from, and a closure that knows how to push gradient to them. Operator overloading builds the graph as a side effect of ordinary arithmetic:

    class Value:
    def __init__(self, data, _children=(), _op=""):
        self.data, self.grad = float(data), 0.0
        self._prev, self._op = tuple(_children), _op
        self._backward = lambda: None

    def __mul__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data * other.data, (self, other), "*")
        def _backward():                       # runs later, during backward()
            self.grad  += other.data * out.grad   # local derivative x upstream
            other.grad += self.data  * out.grad
        out._backward = _backward
        return out

    def backward(self):
        order = topo_order(self)
        self.grad = 1.0
        for v in reversed(order):
            v._backward()

    Each _backward closure captures self, other and out. When it runs, out.grad is already final, because of the reverse topological order. A neuron is then sum(w_i * x_i) + b followed by .tanh(), a layer is a list of neurons, and an MLP is a list of layers. Calling loss.backward() fills in p.grad for every parameter, and gradient descent is p.data -= lr * p.grad.

    Try it: this is a JavaScript port of the Value engine above training a 2→16→16→1 ReLU MLP (337 parameters) on 60 points with a margin loss. Press play. Every step builds a fresh graph and backpropagates through it. Watch the node count: tens of thousands of scalar nodes to compute one loss. Press gradient check to compare the engine's gradient for three random parameters with central differences.

    7. From scalars to tensors

    The scalar engine is perfect for understanding and hopeless for speed. Every multiply is a Python object with a closure. Real frameworks use the same algorithm with nodes that hold whole arrays. A layer becomes one matmul node instead of $d_\text{in}\times d_\text{out}$ multiply nodes, and the local work runs as optimized vectorized code.

    For array-valued nodes the "local derivative" is a Jacobian, which can be enormous. A $1000\times1000$ matmul has a Jacobian with $10^{12}$ entries. Frameworks never build it. Each op instead implements a vector–Jacobian product (VJP): given the upstream gradient $\bar Z$ (same shape as $Z$), return $\bar X$ (same shape as $X$) directly. The rules you need are mostly from lessons 07 and 16:

    ForwardBackward (VJP)
    $Z = X + Y$ (same shape)$\bar X \mathrel{+}= \bar Z$, $\bar Y \mathrel{+}= \bar Z$
    $Z = X + \mathbf{b}$ (broadcast)$\bar{\mathbf{b}} \mathrel{+}= \sum_\text{broadcast axes}\bar Z$ (the "reuse" rule!)
    $Z = X\odot Y$$\bar X \mathrel{+}= Y\odot\bar Z$
    $Z = XW$$\bar X \mathrel{+}= \bar Z W^\top$, $\;\bar W \mathrel{+}= X^\top\bar Z$
    $s = \sum_{ij} X_{ij}$$\bar X \mathrel{+}= \bar s\cdot\mathbf{1}$ (broadcast back)
    $Z = \mathrm{relu}(X)$$\bar X \mathrel{+}= \mathbb{1}[X>0]\odot\bar Z$
    Worked example: deriving the matmul VJP

    $Z_{ik} = \sum_j X_{ij}W_{jk}$. The entry $X_{ij}$ appears in every $Z_{ik}$ of row $i$ (for all $k$), with local derivative $W_{jk}$. Sum over those uses (§5):

    $$\bar X_{ij} = \sum_k \bar Z_{ik}\,W_{jk} = (\bar Z W^\top)_{ij}.$$

    Likewise $W_{jk}$ appears in $Z_{ik}$ for every row $i$: $\bar W_{jk} = \sum_i X_{ij}\bar Z_{ik} = (X^\top\bar Z)_{jk}$. The shapes check out: $\bar X$ is $(N\times d)$ from $(N\times h)(h\times d)$. ✓ Notice that the sum over the batch in $\bar W$ is the reuse rule again: the same weights are used for every example.

    This is literally what loss.backward() does in PyTorch (lesson 19). It records a graph of tensor ops during the forward pass (tensor.grad_fn is the _backward of the node that made it), topologically sorts it, and calls each op's VJP. Every model from here to GPT (lessons 22–24) is trained by this algorithm and nothing else. Workbook part C has you build the tensor version on numpy.

    8. Problems

    Problem 1
    warm-up

    For $L = (ab + c)f$ at $a=2, b=-3, c=10, f=-2$, enter $\partial L/\partial a,\ \partial L/\partial b,\ \partial L/\partial c,\ \partial L/\partial f$.

    Solution

    From the worked example in §2: $\bar a = bf = 6$, $\bar b = af = -4$, $\bar c = f = -2$, $\bar f = ab + c = 4$.

    Problem 2
    warm-up

    Draw the graph for $f(x, y) = (x + y)\cdot(x\cdot y)$ and backprop at $(x, y) = (1, 2)$. Enter $\partial f/\partial x,\ \partial f/\partial y$.

    Solution

    $p = x + y = 3$, $q = xy = 2$, $f = pq = 6$. $\bar p = q = 2$, $\bar q = p = 3$. Through $p$: $\bar x \mathrel{+}= 2$, $\bar y \mathrel{+}= 2$. Through $q$: $\bar x \mathrel{+}= y\bar q = 6$, $\bar y \mathrel{+}= x\bar q = 3$. Total $\bar x = 8$, $\bar y = 5$. Check: $f = x^2y + xy^2$, $f_x = 2xy + y^2 = 8$, $f_y = x^2 + 2xy = 5$. ✓

    Problem 3
    core

    Build $\sigma(z) = 1/(1 + e^{-z})$ only from the primitives in §3: negate, exp, + 1, ** -1. Backprop through those four nodes at $z = 0.5$ and confirm that the result equals $\sigma(z)(1 - \sigma(z))$. Enter the gradient.

    Solution

    $u = -z = -0.5$, $v = e^u = 0.6065$, $w = 1 + v = 1.6065$, $s = w^{-1} = 0.6225$. Backward: $\bar w = -w^{-2} = -0.3875$; $\bar v = \bar w = -0.3875$; $\bar u = v\bar v = -0.2350$; $\bar z = -\bar u = 0.2350$. And $\sigma(1-\sigma) = 0.6225\cdot0.3775 = 0.2350$. ✓ Composites get correct gradients for free. Frameworks still often fuse them into one node with a hand-written backward because it's faster and more numerically stable (lesson 19's custom autograd.Function).

    Problem 4
    core

    $L = (x\cdot x)\cdot x$ built as two multiply nodes. At $x = 2$, list every contribution that gets added into x.grad, and the total.

    Solution

    $s = x\cdot x = 4$, $L = s\cdot x = 8$. Through $L$: $\bar s = x = 2$, $\bar x \mathrel{+}= s = 4$. Through $s$ (both inputs are $x$): $\bar x \mathrel{+}= x\bar s = 4$, twice. Total $4 + 4 + 4 = 12 = 3x^2$. ✓ Three uses, three contributions.

    Problem 5
    core

    Using numerical (central-difference) gradients, how many forward passes does one gradient of GPT-2 small (124 million parameters) cost? Compare with backprop.

    Solution

    Two per parameter: $2.48\times10^8$. Backprop costs about one forward plus one backward, roughly 3 forward-pass equivalents. That's a speed-up of nearly $10^8$. Numerical gradients are still valuable as a test on tiny inputs, which is exactly how the workbook checks your engine.

    Problem 6
    core · derivation

    Derive the VJP for $s = \sum_i X_i$ (to a scalar) and for $Z = X + \mathbf{b}$ where $X$ is $N\times d$ and $\mathbf{b}$ is a length-$d$ vector broadcast over rows. Explain how both are the same rule.

    Solution

    $\partial s/\partial X_i = 1$, so $\bar X = \bar s\,\mathbf{1}$: the sum's gradient copies the upstream value back to every input. For the broadcast, $b_j$ is used in $Z_{ij}$ for every $i$ with local derivative 1, so $\bar b_j = \sum_i \bar Z_{ij}$. Sum forward ⇔ broadcast backward, and broadcast forward ⇔ sum backward. They are each other's transpose, and both are the reuse rule of §5.

    Problem 7
    stretch

    Someone implements backward() with a breadth-first queue from the output instead of a topological sort. Give a graph where this computes a wrong gradient, and say exactly what goes wrong.

    Hint

    Use a node that is consumed both near the output and deep in the graph, like $m$ in §4's figure.

    Solution

    Take $m = ab$, $n = m + c$, $t = \tanh(n)$, $L = t\cdot m$. BFS from $L$ visits $L$, then $t$ and $m$ (both inputs of $L$), so it runs $m$'s _backward after only the contribution from $L$ has arrived. Later $n$'s backward adds the second contribution to m.grad, but $m$ has already pushed its incomplete gradient to $a$ and $b$, so $\bar a$ and $\bar b$ are wrong. A topological order guarantees every consumer of $m$ runs before $m$.

    Problem 8
    stretch

    Count the nodes. A Value-based neuron with $n$ inputs computes $\tanh\!\big(\sum_i w_ix_i + b\big)$ as $n$ multiplies, $n$ additions (starting from $b$), and one tanh. How many non-leaf nodes does a 2→16→16→1 MLP (tanh everywhere, for simplicity) create for one input example?

    Solution

    A neuron with $n$ inputs makes $2n + 1$ nodes. Layer 1: $16(2\cdot2+1) = 80$. Layer 2: $16(2\cdot16+1) = 528$. Layer 3: $1\cdot(2\cdot16+1) = 33$. Total 641 per example, so about 38,000 for a batch of 60 before you even add the loss. A tensor engine needs about 10 nodes for the same batch. That's the motivation for §7.

    9. Quick check

    A model has 1 billion parameters. Roughly how does the cost of one backprop gradient compare to one forward pass?
    Reverse mode visits each node once and does work proportional to that node's forward work. The scalar output is what makes one sweep enough.
    Why does every _backward use += rather than =?
    Multivariable chain rule: the effects along every path add up. (And because of +=, you do need zero_grad between steps.)
    In the backward pass, a + node with upstream gradient 5 sends to its two inputs…
    Both local derivatives of $x+y$ are 1, so the gradient is copied unchanged. Option (c) is max; option (d) is the swap rule of ×.
    Real frameworks implement backward for Z = X @ W (1000×1000 each) by…
    Vector–Jacobian products: the Jacobian is never formed. Backward of a matmul is two matmuls of the same size, which is why backward costs about 2× forward.

    10. Summary

    IdeaRule
    Computation graphDAG of primitive ops; leaves = inputs & parameters
    Backward stepinput.grad += local_derivative * output.grad
    Orderreverse topological (DFS post-order, reversed); seed L.grad = 1
    Reusegradients from all consumers add; broadcast forward ⇔ sum backward
    Gates+ distributes, × swaps, relu/max route
    Tensorseach op supplies a VJP; never materialize Jacobians
    Costbackward ≈ 2× forward, independent of #parameters
