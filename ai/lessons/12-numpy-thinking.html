NumPy thinking: vectorization & broadcasting

Every model in the rest of this course is a few lines of array code: a matrix multiply, a broadcasted add, a reduction. Writing that code well is a skill of its own. You stop thinking "for each row, for each column" and start thinking in whole arrays and their shapes. This lesson builds that habit from the bottom up, starting with how an array actually sits in memory.

By the end you can

  • Explain an array as buffer + shape + strides + dtype, and predict which operations are free views and which copy.
  • Say exactly which index disappears when you reduce with axis=k, and use keepdims to keep shapes compatible.
  • Apply the three broadcasting rules in your head, and spot the classic (n,) vs (n,1) bug.
  • Use boolean and fancy indexing, and replace Python loops with vectorized code that runs 100–1000× faster.
  • Read and write np.einsum as a compact notation for any sum of products.

    1. An array is a typed block of memory

    A Python list of floats is a list of pointers to separate float objects scattered around the heap. Each one carries a type tag and a reference count. A NumPy array is the opposite: one contiguous block of raw bytes, plus a small header that says how to read it. The header has four parts:

    FieldExampleMeaning
    dtypefloat64how to read each element: 8 bytes, IEEE double
    shape(3, 4)the logical grid: 3 rows, 4 columns. ndim = len(shape)
    strides(32, 8)bytes to jump to move one step along each axis
    data pointer(an address)where element [0, 0] lives in the buffer

    Because every element has the same type and size, the CPU can stream through the buffer without asking "what is this object?" at each step. That single fact explains most of NumPy's speed (section 6).

    The dtype matters in ML more than you might expect. float64 is NumPy's default; deep learning mostly uses float32, and large models train in 16-bit formats (float16, bfloat16) to halve memory and double throughput. Integer arrays (int64) hold labels and token ids. Mixing dtypes silently upcasts: int + float gives float, and float32 + float64 gives float64.

    Worked example: how big is a batch?

    A batch of 64 RGB images at 224×224 is an array of shape (64, 3, 224, 224). It has $64\cdot 3\cdot 224\cdot 224 = 9{,}633{,}792$ elements. In float32 (4 bytes each) that's $38{,}535{,}168$ bytes, about 38.5 MB. In float64 it's 77 MB. Same numbers, twice the memory and twice the memory traffic. That's why frameworks default to 32-bit.

    2. Memory layout and strides

    Memory is one-dimensional. A 2-D array has to be flattened somehow. NumPy's default is row-major ("C order"): row 0 first, then row 1, and so on. To find element $[i, j]$ you jump $i$ rows and $j$ columns:

    $$\text{byte offset of } a[i,j] = \text{offset} + i\cdot s_0 + j\cdot s_1,$$

    where $(s_0, s_1)$ are the strides. For a float64 array of shape $(3,4)$, moving one column is 8 bytes and moving one row skips 4 elements, so the strides are $(32, 8)$.

    Here's the payoff. Many operations don't touch the data at all. They just write a new header over the same buffer. That new header is called a view. Transposing swaps the strides to $(8, 32)$. Taking every other column doubles the column stride. Reversing the rows makes a stride negative. All of these are $O(1)$, no matter how big the array.

    Try it: pick a view of a = np.arange(12.).reshape(3, 4) and click any cell of the logical grid. The strip at the bottom is the actual buffer: the numbers above it show the order in which the view visits memory. With a.T, look at how the traversal jumps around instead of streaming left to right. Then pick a.T.copy(): a new buffer appears, laid out in the transposed order.

    Two flags summarize the layout. A view is C-contiguous if walking it in row-major order visits consecutive memory, and F-contiguous (Fortran order) if walking it column by column does. a.T of a C-contiguous array is F-contiguous. Some operations need contiguous input. reshape on a non-contiguous view, for instance, may be forced to copy. Contiguity also matters for speed, because the CPU loads memory in 64-byte cache lines. Streaming through consecutive addresses uses all 8 doubles on each line. Jumping by a large stride uses one double and wastes the rest.

    PyTorch tensors work exactly the same way: storage + sizes + strides + offset (lesson 19). x.T, x[:, ::2] and x.view(...) are free. The occasional error "view size is not compatible with input tensor's size and stride" is this section in action: you asked for a reshape that strides can't express, so you need .contiguous() or .reshape, which copies.

    3. Axes and reductions

    A reduction such as sum, mean, max or argmax collapses an axis. The one rule to remember:

    X.sum(axis=k) sums over index $k$, so axis $k$ disappears from the shape. For $X$ of shape $(4, 5)$, axis=0 sums down the columns, giving shape $(5,)$, one number per column. axis=1 sums along the rows, giving shape $(4,)$, one number per row. In formulas, X.sum(axis=0) is $\sum_i X_{ij}$, a function of $j$ only.

    People find "axis 0 gives per-column results" backwards at first. Read it as "the axis you name is the one you sum over". In ML your data matrix is usually $(n, d)$ with one example per row, so X.mean(axis=0) is the mean feature vector (average over examples) and X.sum(axis=1) gives a per-example total.

    keepdims=True keeps the reduced axis with length 1: shape $(4,5) \to (1,5)$ instead of $(5,)$. That small difference decides whether the result broadcasts back against $X$ the way you want (next section).

    Try it: choose an axis and an operation, then press squash to watch the cells collapse along that axis into the result. Notice which dimension of the shape vanishes. Toggle keepdims and watch the result keep a length-1 axis instead.

    4. Broadcasting

    You constantly need to combine arrays of different shapes. Subtract the column means $(d,)$ from a data matrix $(n,d)$. Add a bias $(k,)$ to every row of $(n,k)$ activations. Compare every point with every other point. Broadcasting is NumPy's rule for when such an operation is allowed and what it means. Compare the shapes from the right:

    1. If the shapes have different lengths, pad the shorter one on the left with 1s.
    2. Two dimensions are compatible if they are equal, or if one of them is 1.
    3. A dimension of size 1 is stretched (virtually repeated) to match the other. The result has the larger size in every dimension.

    If any pair of dimensions fails rule 2, you get ValueError: operands could not be broadcast together. The stretching is free. NumPy implements it as a view with stride 0 along the stretched axis, so the "copies" never exist in memory.

    Try it: choose shapes for A and B. The table aligns them from the right. Solid cells are real data; faded cells are the virtual copies broadcasting creates. Try (3,1) + (1,4): two thin arrays make a full 3×4 table, the "outer sum" trick behind every pairwise computation. Then try (3,4) + (3,) and see why it fails.
    Worked example: all pairwise distances, no loops

    Take $X$ with shape $(n, d)$ ($n$ points) and $Y$ with shape $(m, d)$. We want $D_{ij} = \|\mathbf{x}_i - \mathbf{y}_j\|^2$ with shape $(n, m)$.

    Step 1: insert axes so the shapes line up for an "every $i$ with every $j$" table. X[:, None, :] has shape $(n, 1, d)$ and Y[None, :, :] has shape $(1, m, d)$.

    Step 2: subtract. Aligning from the right, $d$ matches $d$, $1$ stretches to $m$, and $n$ meets the stretched 1. The result is $(n, m, d)$, and entry $[i,j,:]$ is $\mathbf{x}_i - \mathbf{y}_j$.

    Step 3: square and .sum(axis=-1). The last axis ($d$) disappears, leaving $(n, m)$. ✓

    The catch is that the intermediate has $nmd$ numbers. Expanding $\|\mathbf{x}-\mathbf{y}\|^2 = \|\mathbf{x}\|^2 + \|\mathbf{y}\|^2 - 2\,\mathbf{x}\cdot\mathbf{y}$ (lesson 01, problem 5) avoids it. That gives one matrix multiply $XY^\top$ of shape $(n,m)$, plus sq_x[:, None] + sq_y[None, :], another outer sum. You'll write both in the workbook.

    The classic broadcasting bug. Suppose y has shape (100, 1) (a column you loaded from a file) and your predictions y_hat have shape (100,). Then y - y_hat has shape (100, 100): every target minus every prediction. np.mean((y - y_hat)**2) happily returns a number, but it's the wrong one, and you get no error. Your linear regression (lesson 13) will train to garbage. Defense: assert shapes, and use keepdims or .ravel() deliberately.

    Worked example: row-wise softmax, numerically stable

    Given logits $Z$ of shape $(n, K)$ (one row per example), softmax each row: $P_{ik} = e^{Z_{ik}} / \sum_{k'} e^{Z_{ik'}}$. With logits around 1000, np.exp overflows to inf and you get inf/inf = nan. The fix rests on one identity. For any constant $c$,

    $$\frac{e^{z_k - c}}{\sum_{k'} e^{z_{k'} - c}} = \frac{e^{-c}\,e^{z_k}}{e^{-c}\sum_{k'} e^{z_{k'}}} = \frac{e^{z_k}}{\sum_{k'} e^{z_{k'}}}.$$

    Pick $c = \max_k z_k$. Then the largest exponent is $e^0 = 1$, so nothing overflows, and the denominator is at least 1, so nothing divides by zero. In code, shapes are the whole story:

    Z = Z - Z.max(axis=1, keepdims=True)   # (n,K) - (n,1): per-row shift
E = np.exp(Z)                          # (n,K)
P = E / E.sum(axis=1, keepdims=True)   # (n,K) / (n,1)

    Drop keepdims and the second line becomes $(n,K) - (n,)$. That's an error when $n \ne K$. When $n = K$ it's a silent wrong answer, because each row gets shifted by some other row's max. You'll reuse this softmax in lessons 14, 22 and 24.

    5. Fancy and boolean indexing; views vs copies

    Indexing comes in two kinds, and the difference is exactly the view/copy line from section 2:

    • Basic indexing uses integers, slices start:stop:step, None and .... The result can always be described by a new offset, shape and strides, so it's a view. Writing into it writes into the original.
    • Advanced indexing uses an integer array (fancy) or a boolean array (mask). The selected elements can be in any order, can repeat, and can be any subset. No stride pattern can describe that, so the result is a copy.
    Try it: in mask mode, drag the threshold and watch x > t pick out elements into a new, shorter array. Switch to fancy mode: indices can repeat and come in any order, so the output can't be a strided view of x. The np.where mode keeps the shape and chooses element-wise between two arrays.
    ExpressionView or copy?Why
    a[1:3], a[:, ::2], a.T, a[None]viewnew strides/offset over the same buffer
    a.reshape(...)view if possiblecopies when strides can't express it
    a[[0, 2]], a[a > 0]copyarbitrary selection
    a.flatten(), a.copy(), a + 0copyalways new memory
    a[a > 0] = 0, a[[0, 2]] += 1in-place writeindexing on the left of = modifies a

    Two indexing idioms you'll use in nearly every lesson from here on. One-hot encoding: O = np.zeros((n, K)); O[np.arange(n), y] = 1. Picking each example's probability of its true class (cross-entropy, lesson 14): P[np.arange(n), y]. Both pair row $i$ with column $y_i$.

    6. Vectorization vs loops

    "Vectorize" means replacing a Python loop over elements with one call that loops in compiled C. The speedups are not small. These are measured numbers from a laptop (Apple M4 Pro, Python 3.14, NumPy 2.5, best of several runs):

    Try it: switch benchmarks. The axis is logarithmic: each gridline is 10× slower. Note that looping in Python over a NumPy array is even slower than looping over a list, since every x[i] boxes a fresh Python float. Numbers will differ on your machine; the ratios are what matter.

    Where does a 500× gap come from? A Python s += v*v runs through the interpreter. Every iteration means fetching bytecode, checking the types of s and v, allocating a result object and updating reference counts: tens of nanoseconds of bookkeeping for one nanosecond of arithmetic. A NumPy reduction does the type check once, then runs a tight compiled loop over contiguous typed memory. The CPU's SIMD units do 2–8 multiplies per instruction, and the prefetcher streams the cache lines in ahead of time. Matrix multiply goes further. @ calls BLAS, which tiles the problem to fit the caches and uses every core. That's how a 128×128 matmul gets about 3600× faster than a triple loop.

    The rule of thumb: Python is for orchestration, arrays are for arithmetic. A loop over 10 epochs or 5 hyperparameters is fine. A loop over a million elements, or over the rows of a data matrix, is a smell. Look for the broadcasting or reduction that expresses it in one shot. Be careful with memory, though. The broadcast version of pairwise distances built a $500\times500\times16$ intermediate. At $n=m=10{,}000$, $d=128$ that would be 102 GB (problem 5).

    7. einsum: one notation for every sum of products

    Dot products, matrix–vector products, matmul, batched matmul, outer products, traces, transposes: each is "multiply some entries and sum over some indices". Physicists write these in Einstein notation: name every index, and any index that doesn't appear in the output gets summed. np.einsum takes exactly that:

    $$C_{ik} = \sum_j A_{ij} B_{jk} \quad\Longleftrightarrow\quad \texttt{np.einsum("ij,jk->ik", A, B)}$$

    Read the spec as nested loops. Every letter is a loop variable. Letters on the right of -> are free and index the output. Letters that appear only on the left are summed. The body multiplies one entry from each operand and accumulates.

    Try it: step through the specs. Free indices are blue and summed ones pink. The readout shows the equivalent loop nest and the everyday NumPy spelling. Note ii->i (diagonal) and ij->ji (transpose): no sum at all, just re-indexing.

    Attention scores in a transformer (lesson 22) are einsum("bhtd,bhsd->bhts", Q, K): batch $b$, head $h$, query position $t$, key position $s$, summed over the feature dimension $d$. Once you can read that string, you can read the core of any transformer implementation. Write it out for your own shapes. It documents itself.

    8. Problems

    Work these out with pencil and paper first, then check in a Python shell. Predicting shapes before running the code is the skill being trained.

    Problem 1
    warm-up

    Let a = np.arange(12, dtype=np.float64).reshape(3, 4), with strides $(32, 8)$. What are the strides (in bytes) of a[::2, 1:]? Enter them as two numbers.

    Solution

    Taking every second row doubles the row stride: $2\times32 = 64$. Starting at column 1 only changes the offset (by 8 bytes), not the column stride, which stays 8. So the strides are $(64, 8)$ and the shape is $(2, 3)$.

    Problem 2
    warm-up

    Same array. At what byte offset from the start of the buffer does a[2, 1] live? And what about a.T[1, 2]?

    Solution

    $2\cdot 32 + 1\cdot 8 = 72$. That's element number 9, and indeed a[2,1] == 9. For the transpose, the strides are $(8, 32)$, so a.T[1, 2] is at $1\cdot8 + 2\cdot32 = 72$: the same element, as it must be.

    Problem 3
    core

    What is the shape of A + B if A.shape == (8, 1, 6, 1) and B.shape == (7, 1, 5)? Enter the four dimensions.

    Hint

    Pad B on the left to $(1, 7, 1, 5)$, then compare dimension by dimension.

    Solution

    Align: $(8,1,6,1)$ against $(1,7,1,5)$. Each pair has a 1 in it or is equal: $8/1 \to 8$, $1/7\to7$, $6/1\to6$, $1/5\to5$. Result $(8,7,6,5)$.

    Problem 4
    core

    Let x = np.array([[1, 2, 3], [4, 5, 6]]). Compute x.sum(axis=0) (enter the three numbers), then say what x.max(axis=1) and x.mean(axis=0, keepdims=True).shape are.

    Solution

    Axis 0 (the row index) disappears, so you sum down each column: $(1+4, 2+5, 3+6) = (5, 7, 9)$. x.max(axis=1) is the max of each row, [3, 6]. With keepdims the mean has shape $(1, 3)$.

    Problem 5
    core

    You compute pairwise distances by broadcasting, X[:, None, :] - Y[None, :, :], with $n = m = 10{,}000$ points in $d = 128$ dimensions, in float64. How many gigabytes (10⁹ bytes) does the intermediate need? How big is the final $(n, m)$ matrix?

    Solution

    $10^4\cdot10^4\cdot128\cdot 8 = 1.024\times10^{11}$ bytes, or 102.4 GB. The output is $10^8 \cdot 8$ bytes, 0.8 GB. The Gram-matrix trick $\|\mathbf{x}\|^2 + \|\mathbf{y}\|^2 - 2XY^\top$ never builds the 3-D tensor, so it needs about 0.8 GB. That's why every serious library uses it.

    Problem 6
    core · proof

    Define $\operatorname{logsumexp}(\mathbf{z}) = \log\sum_k e^{z_k}$. Show that $\operatorname{logsumexp}(\mathbf{z}) = m + \log\sum_k e^{z_k - m}$ for $m = \max_k z_k$, and that the right-hand side never overflows. Then show that $\log \operatorname{softmax}(\mathbf{z})_k = z_k - \operatorname{logsumexp}(\mathbf{z})$.

    Solution

    $\sum_k e^{z_k} = e^m \sum_k e^{z_k - m}$. Take logs: $\log e^m + \log\sum_k e^{z_k-m} = m + \log\sum_k e^{z_k-m}$. Each $z_k - m \le 0$, so each term is in $(0,1]$, and the term for the max equals 1. So the sum lies in $[1, K]$ and its log in $[0, \log K]$: no overflow, and no log(0). Finally, $\log\frac{e^{z_k}}{\sum e^{z_{k'}}} = z_k - \log\sum e^{z_{k'}}$. This "log-softmax" is how cross-entropy is computed in practice (lesson 14). You never form the probabilities and then take their log.

    Problem 7
    core

    y.shape == (100, 1) and y_hat.shape == (100,). What is the shape of y - y_hat? Write a one-line expression for what np.mean((y - y_hat)**2) actually computes, and give two ways to fix it.

    Solution

    $(100, 100)$: entry $[i,j] = y_i - \hat y_j$. The mean is $\frac{1}{100^2}\sum_{i,j}(y_i - \hat y_j)^2$, the average over all pairs, not matched pairs. Fixes: y = y.ravel() (or y[:, 0]), or y_hat = y_hat[:, None]. Add assert y.shape == y_hat.shape to your loss function and this bug can never come back.

    Problem 8
    stretch

    Write np.einsum specs for: (a) the trace of a square matrix; (b) the row-wise dot products of two $(n,d)$ arrays, giving $(n,)$; (c) the outer product of two vectors; (d) attention scores for $Q$ of shape $(b, t, d)$ and $K$ of shape $(b, s, d)$, giving $(b, t, s)$.

    Solution

    (a) "ii->". (b) "nd,nd->n", the same as (A*B).sum(1). (c) "i,j->ij", the same as u[:, None] * v[None, :]. (d) "btd,bsd->bts", the same as Q @ K.transpose(0, 2, 1). In each case $d$ (or $i$ in (a)) is the index that is missing from the output and therefore summed.

    Problem 9
    stretch

    Let x be a contiguous float32 array of length 10. You want the $(7, 4)$ array whose row $i$ is x[i:i+4] as a view, built with as_strided. What strides (bytes) do you pass?

    Solution

    Moving one column means moving one element: 4 bytes. Moving one row means the window starts one element later: also 4 bytes. So the strides are $(4, 4)$. Rows overlap in memory, which no copy could do. 28 logical elements are backed by just 10 stored ones. Write into it and you'd change several rows at once, which is why the workbook makes it read-only.

    9. Quick check

    Which of these returns a view of a (no copy)?
    Slices are basic indexing: same buffer, new offset and strides. Boolean and integer-array indexing select arbitrary elements and must copy. flatten always copies; ravel returns a view when it can.
    X.shape == (32, 10). You want to subtract each row's mean from that row. Which line is correct?
    X.mean(axis=1) has shape $(32,)$, which aligns with the trailing 10, so (a) raises an error. With keepdims it's $(32,1)$, which stretches across the columns. (c) subtracts column means. That's a different (also common) operation. (d) subtracts one global scalar.
    Why is x @ x hundreds of times faster than a Python loop accumulating v*v, even on one core?
    The arithmetic is the same. The difference is bookkeeping per element, plus SIMD and cache-friendly streaming. Plain NumPy never uses the GPU.
    In np.einsum("bij,bjk->bik", A, B), which index is summed over?
    Only j is missing from the output, so it's summed. b appears in both inputs and the output, so it's a batch index that's matched but not summed. This is batched matmul.
